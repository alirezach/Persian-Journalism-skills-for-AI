# بسته‌بندی اسکیل‌ها

## چیدمان OpenCode ۰.۱.۰

`build-opencode.py` از سه سازندهٔ کانونی موجود، بستهٔ مستقل مهارت‌های انتخاب‌شده را در حافظه می‌سازد و بدون تغییر فایل‌های بسته، زیر `.opencode/skills/<name>/` قرار می‌دهد. پیکربندی نسخه‌ها در [bundle.json](../../adapters/opencode/bundle.json) است. سازنده‌های قبلی تغییر نکرده‌اند و ZIPهای تاریخی بازنویسی نمی‌شوند.

```bash
python3 scripts/packaging/build-opencode.py --output dist/pjai-opencode-0.1.0.zip
python3 scripts/packaging/build-opencode.py --skills persian-editing data-analysis --output dist/pjai-opencode-0.1.0-selected.zip
python3 -m unittest discover -s tests -p 'test_opencode_build.py' -v
```

Python 3.10+ و کتابخانهٔ استاندارد کافی است. مقصد باید ZIP تازه باشد؛ نصب یا دانلود وابستگی، اجرای مدل و OpenCode انجام نمی‌شود. کد سازنده‌های محلی از checkout مورداعتماد import می‌شود؛ این مرز امنیتی نیست. از `--help` برای مشاهدهٔ گزینه‌ها استفاده کنید.

خروجی شامل منابع کامل مهارت‌های منتخب، `START-HERE-fa.md` و `BUNDLE-MANIFEST.json` است. manifest نسخه و وضعیت مهارت‌ها، هش آرشیوهای داخلی، سازنده‌ها، پیکربندی و فایل‌های خروجی را ثبت می‌کند؛ هش خودش ثبت نمی‌شود. ترتیب، زمان، مجوز و ZIP_STORED ثابت‌اند. بررسی بایت‌های واقعی و تکرارپذیری در محیط اجرا در [گزارش فنی](../../docs/evaluations/opencode-0.1.0-technical.md) ثبت می‌شود، نه به‌عنوان سازگاری بین سیستم‌عامل‌ها.

کنترل‌ها شامل نام/نسخه/وضعیت، حضور ورودی و مجوز، تطبیق manifest و هش خروجی‌ها، رد مسیر غیرمجاز، symlink، تعارض نام و فایل/پوشه، فایل غیرمتنی و سقف اندازه‌اند. نحو metadata محدود به قالب این پروژه است؛ parser عمومی YAML یا اعتبارسنج رسمی Agent Skills نیست. منابع هر بسته با قواعد همان سازندهٔ کانونی حل می‌شوند؛ قواعد قدیمی ویرایش و بسته‌های دیگر یکسان فرض نمی‌شوند. پیوندهای وب و لنگرها دوباره تأیید نمی‌شوند.

نصب انتخابی دستی و کنترل تعارض در [راهنمای OpenCode](../../docs/adapters/opencode.md) آمده است. سازنده هیچ `AGENTS.md`، تنظیم permission، کلید API یا فایل تنظیمات میزبان را ایجاد/جایگزین نمی‌کند. منابع مشترک جاری ممکن است با بستهٔ تاریخی فرق داشته باشند؛ هش تازه و گزارش آن مستقل‌اند. ساخت، وضعیت planned/experimental را ارتقا نمی‌دهد و سابقهٔ پذیرش را به بستهٔ تازه منتقل نمی‌کند.

## شش نامزد متنی ۰.۱.۱

`build-candidates.py` فقط source-verification، fact-checking، research-synthesis، data-analysis، data-visualization و data-journalism را با وضعیت `planned` می‌سازد. Python 3.10+ و کتابخانهٔ استاندارد کافی‌اند. سازنده‌های قدیمی ویرایش و ترجمه تغییر نکرده‌اند.

```bash
python3 scripts/packaging/build-candidates.py --skill data-analysis --output dist/data-analysis-0.1.1-planned.zip
python3 -m unittest discover -s tests -p 'test_candidate_build.py' -v
```

هر اسکیل `build-manifest.json`، `package-README.md` و `package-NOTICES.md` خودش را دارد. فهرست منابع صریح است؛ پیمایش خودکار همهٔ مخزن انجام نمی‌شود. راهنماها، قراردادها، استانداردها، schemaها و فرم‌های لازم داخل ZIP قرار می‌گیرند. پیوندهای نقش همکار یا زمینهٔ مخزن که همراه نیستند، در manifest صریح و به commit مبنای ثابت محدودند؛ وجود پیوند نصب یا اجرای همکار نیست.

حد هر فایل ۱ MiB، مجموع ورودی‌ها ۴ MiB و حداکثر منابع ۹۶ فایل است. فقط منابع متنیِ نواحی مجاز و پسوندهای تعیین‌شده پذیرفته می‌شوند. مسیر مطلق یا پیمایش، symlink، نام تکراری یا برخورد فایل و پوشه، خروجی موجود و پیوند محلی حل‌نشده رد می‌شوند. حالت experimental یا tested پذیرفته نمی‌شود؛ ارتقا جزو کار سازنده نیست.

پیوندهای سادهٔ Markdown از محل فایل مبدأ به محل واقعی داخل بسته بازنویسی می‌شوند. ارجاع URN در schemaها با شناسهٔ schemaهای همراه تطبیق داده می‌شود؛ لنگر عنوان، جزء JSON Pointer و نشانی بیرونی بررسی یا دریافت نمی‌شوند. metadata با کنترل محدود همین پروژه خوانده می‌شود، نه parser عمومی YAML یا اعتبارسنج رسمی Agent Skills.

`manifest.json` خروجی، هش سازنده و پیکربندی و هش ورودی/خروجی هر فایل را نگه می‌دارد؛ هش خودش را ندارد. ترتیب، زمان، مجوز و روش ذخیرهٔ ZIP ثابت‌اند. در Python 3.12.13 روی محیط Linux ثبت‌شده، ساخت دوبارهٔ شش نامزد بایت‌های یکسان داد؛ بازتولید بین محیط‌ها آزموده نشده است.

۴۰ آزمون واحدِ مختص سازنده با ورودی مصنوعی گذشت. کنترل ZIPهای واقعی از آزمون واحد و ارزیابی رفتاری جدا ثبت شده است. [گزارش فنی](../../docs/evaluations/six-skills-0.1.1-technical.md) و [تصمیم‌نامه](../../docs/six-skills-0.1.1-candidate-decision.md) دامنه و محدودیت‌ها را توضیح می‌دهند. سناریوهای رفتاری فقط آماده شده‌اند؛ نصب، داوری مستقل، Release و tag انجام نشده است.

این سازنده اسکن اسرار، ممیزی حقوقی، sandbox امنیتی یا ابزار انتشار نیست. checkout و manifest باید مورداعتماد باشند؛ تغییر هم‌زمان فایل‌سیستم خارج از تضمین است. schemaهای همراه ابزار اعتبارسنج رکورد را اجرا نمی‌کنند. فایل‌های ZIP خروجی تحویل‌اند و به‌عنوان فایل باینری در مخزن ثبت نمی‌شوند.

## ساخت بستهٔ مستقل ویرایش فارسی

این سازنده فقط `persian-editing` را بسته‌بندی می‌کند، نه همهٔ اسکیل‌های آینده. Python 3.10 یا بالاتر و کتابخانهٔ استاندارد کافی است؛ نصب شبکه‌ای ندارد. نسخهٔ آزموده‌شده در گزارش ارزیابی ثبت می‌شود.

از ریشهٔ مخزن:

```bash
python3 scripts/packaging/build-skill.py --help
python3 scripts/packaging/build-skill.py --output dist/persian-editing-0.1.3.zip
python3 tests/test_editing_build.py
node tests/editing-package.test.cjs
```

فرمان آخر به js-yaml مشخص‌شده در package.json نیاز دارد. ساخت ZIP به Node، مدل یا کتابخانهٔ جانبی نیاز ندارد. کد خروج سازنده: صفر برای ساخت موفق، ۲ برای ورودی/ساخت ناموفق. گزارش موفقیت JSON روی stdout و خطای محدود روی stderr است. ورودی تعاملی ندارد و فایل موجود را بازنویسی نمی‌کند؛ برای ساخت مجدد مقصد تازه بدهید.

## چه چیزی وارد بسته می‌شود؟

فقط فایل‌های صریحاً فهرست‌شده در `skills/persian-editing/build-manifest.json`: دستور اصلی، پنج راهنمای ویرایش، چهار استاندارد مشترک، دو پروفایل، یک ابزار Python اختیاری، مجوز و اعلان منابع. یک manifest خروجی نیز ساخته می‌شود؛ مجموع ۱۶ فایل. منبع هر فایل و SHA-256 قبل و بعد از بازنویسی مسیر ثبت می‌شود. خود manifest هش خودش را ندارد. شناسهٔ commit از محیط حدس زده نمی‌شود؛ هش فایل‌ها و سازنده مبنای بازتولیدند.

مسیر منابع مشترک فقط در پیوندهای مشخص دستور اصلی بازنویسی می‌شود. فایل منبع دست‌نخورده می‌ماند. منابع مشترک در مخزن یک نسخه دارند؛ کپی داخل ZIP تولیدشده است. بایت‌های ZIP با محتوای یکسان در محیط آزموده‌شده تکرارپذیرند: ترتیب، زمان و مجوز ثابت و بدون فشرده‌سازی. بازتولید بین نسخه‌های متفاوت Python یا سیستم‌عامل‌ها هنوز آزموده نشده است.

## حدود کنترل

مسیر مطلق، پیمایش `..`، مسیر ویندوزی، symlink منبع و مقصد، نام تکراری، فایل غیرعادی، خروجی موجود و پیوند محلی حل‌نشده رد می‌شوند. ورودی هر فایل حداکثر ۱ MiB و مجموع فایل‌های بسته ۴ MiB است؛ حداکثر ۳۲ فایل منبع. فایل‌های UTF-8 از نواحی عمومیِ مجاز انتخاب می‌شوند، نه با پیمایش تمام مخزن.

بررسی پیوند محدود به نحو سادهٔ Markdown پروژه است؛ parser کامل Markdown، HTML یا اعتبارسنج لنگرهای عنوان نیست. پیوند وب باز نمی‌شود. اعتبارسنج رسمی `skills-ref` اجرا نشده است. metadata با آزمون‌های محلی بررسی می‌شود؛ سازنده به‌تنهایی اعتبار معنایی دستور یا کامل‌بودن همهٔ قواعد را تضمین نمی‌کند.

کد، manifest و checkout باید مورداعتماد باشند. این ابزار sandbox، ضد‌بدافزار، اسکن اسرار، ناشناس‌ساز یا ابزار صدور مجوز انتشار نیست. مجازبودن مسیر مانع وجود متن حساس در همان فایل نمی‌شود. تغییر هم‌زمان فایل‌سیستم و ورودی خصمانه خارج از دامنهٔ تضمین است. کنترل symlink محدودیت شبکه‌فایل‌سیستم یا مرز امنیتی سیستم‌عامل ایجاد نمی‌کند.

مقدار `model_evaluation: not_run` در گزارش سازنده فقط می‌گوید خودِ عملیات ساخت مدل را اجرا نکرده است؛ سابقهٔ جداگانهٔ ارزیابی هر نسخه در کاتالوگ و پروندهٔ ارزیابی آمده است.

نصب در محصول، فراخوانی مدل، ذخیرهٔ متن واقعی کاربران و انتشار GitHub جزو عملیات سازنده نیست. ابزار تبدیل فقط از مسیر دقیق `scripts/editing/normalize_transcribed_fa.py` به `scripts/normalize_transcribed_fa.py` بسته‌بندی می‌شود؛ مجوز عمومی ورود فایل Python اضافه نشده است. سازنده هیچ فایل Python بسته را هنگام ساخت اجرا نمی‌کند و خودش همراه بسته توزیع نمی‌شود. اجرای آزمایشی ابزار پس از استخراج، آزمون نصب در یک محصول نیست.

## سازندهٔ جداگانهٔ ترجمه

بخش‌های بالا مخصوص سازندهٔ ویرایش و سابقهٔ آن‌اند. فایل `build-skill.py` تغییر نکرده است. سازندهٔ `build-translation.py` فقط ترجمه را بسته‌بندی می‌کند؛ سازندهٔ عمومی همهٔ اسکیل‌ها نیست. وضعیت را از manifest صریح می‌گیرد و با دستور اصلی تطبیق می‌دهد؛ فقط planned و experimental مجازند و ساخت، وضعیت را خودکار ارتقا نمی‌دهد.

```bash
python3 scripts/packaging/build-translation.py --output dist/humanities-translation-0.1.0-experimental.zip
```

manifest جاری به تصمیم صاحب پروژه experimental است. نام فایل خروجی وضعیت را تعیین نمی‌کند. برای بازسازی نامزد تاریخی planned باید منابع و سازندهٔ همان نسخهٔ تاریخی استفاده شوند؛ تغییر نام ZIP جدید، آن را به بستهٔ قبلی تبدیل نمی‌کند.

Python 3.10+ و کتابخانهٔ استاندارد کافی‌اند. ۱۴ منبع مجاز در `skills/humanities-translation/build-manifest.json` صریح‌اند؛ خروجی همراه `manifest.json` مجموعاً ۱۵ فایل است. README و اعلان منابع از دو متن مخصوص بسته تولید می‌شوند. مسیر پیوندها در تمام فایل‌های Markdown، از جمله راهنماهای فرعی، نسبت به محل همان فایل حل و به مقصد داخل بسته بازنویسی می‌شود؛ شیوهٔ حل مسیر با سازندهٔ قدیمی ویرایش یکی فرض نشود.

سازنده نام‌ها، محدودهٔ مسیر، نبود symlink، اندازه، UTF-8، تطابق وضعیت و نسخهٔ دستور اصلی با manifest را کنترل می‌کند. فهرست ورودی با فهرست محدود داخل کد تطبیق دارد. ورودی هر فایل حداکثر ۱ MiB و مجموع ۴ MiB است. خروجی موجود بازنویسی نمی‌شود. کد خروج صفر برای ساخت موفق و ۲ برای خطای ورودی یا ساخت است. هیچ فایل منبعی تغییر نمی‌کند.

کنترل پیوند فقط نحو سادهٔ inline Markdown را پوشش می‌دهد؛ HTML، reference links و نحو پیچیده پشتیبانی نمی‌شوند. پیوند محلی خروجی باید داخل بسته حل شود. لنگر عنوان و نشانی خارجی بررسی نمی‌شوند. metadata با الگوی محدود متنی بررسی می‌شود، نه parser عمومی YAML. کد جدید، اسکن امنیتی یا ممیزی مجوز انجام نمی‌دهد و در برابر تغییر هم‌زمان فایل‌سیستم تضمین ندارد.

manifest شامل هش سازنده، پیکربندی، ورودی و خروجی فایل‌ها و تغییر پیوندهاست؛ هش خودش را ثبت نمی‌کند. baseline_revision نسخهٔ مبنای پیش از همان ساخت است و برای تمام ورودی‌ها ادعای commit مشترک نمی‌سازد. زمان، ترتیب و مجوز ZIP ثابت‌اند، اما بازتولید بین محیط‌ها یا نسخه‌های Python آزموده نشده است.

در 2026-11-15 ابتدا نامزد planned و سپس با تصمیم صریح، بستهٔ experimental ساخته شد. بستهٔ قبلی و ماتریس تاریخی آن حفظ شده‌اند. فقط کنترل‌های داخلی ساخت و تطبیق محتویات و هش آرشیو انجام شده‌اند؛ هیچ مجموعه‌آزمون پروژه، ارزیابی مدل یا نصب اجرا نشد. فرمان‌های آزمونِ بخش ویرایش، سابقهٔ همان ابزارند و دستور اجرای این مرحله نیستند. Release و tag ساخته نشدند. تصمیم و هش هر دو بسته در [تصمیم‌نامهٔ ارتقا](../../docs/humanities-translation-0.1.0-experimental-decision.md) ثبت است.
