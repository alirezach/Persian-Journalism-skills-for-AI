# اعتبارسنج عمومی رکوردها

نسخهٔ ابزار: `0.3.0-tooling`، آزمایشی. قرارداد رکورد: `0.1.0` با JSON Schema Draft-07.

«عمومی» یعنی قابل‌اجرا روی فایل‌های پروژه، نه اعتبارسنج هر نوع JSON. پنج نوع `source`، `claim`، `dataset`، `finding` و `handoff` پشتیبانی می‌شوند. صحت ادعا، کیفیت روش، کفایت حفاظت از منبع و اجازهٔ انتشار از نتیجهٔ این ابزار به دست نمی‌آیند.

## آماده‌سازی

به Node.js 20 یا جدیدتر نیاز است؛ اجرای ثبت‌شده با Node.js `v22.23.1` بوده است. از ریشهٔ مخزن کار کنید. وابستگی اجرایی Ajv است؛ js-yaml فقط برای آزمون پروفایل‌ها لازم است. نسخه‌های مستقیم در [package.json](../../package.json) مشخص‌اند.

اگر وابستگی‌ها از قبل موجود نیستند، پس از بررسی بسته و طبق سیاست محیط می‌توان نصب کرد:

```bash
npm install --ignore-scripts --no-audit --no-fund
```

این دستور نصب و فرمان‌های npm در محیط بررسی اجرا نشده‌اند؛ آزمون‌ها با Node و کتابخانه‌های ازپیش‌نصب‌شده اجرا شدند. فایل قفل کامل وابستگی‌های فرعی و ممیزی زنجیرهٔ تأمین هنوز وجود ندارند. حذف اجرای اسکریپت نصب، ممیزی امنیتی محسوب نمی‌شود.

## اجرای خط فرمان

نمونهٔ کاملاً مصنوعی همراه مخزن:

```bash
node scripts/validation/validate-records.cjs --input examples/records/synthetic-bundle.json
```

فایل واقعی را با مسیر محلی صریح معرفی کنید. فایل به مخزن کپی نمی‌شود:

```bash
node scripts/validation/validate-records.cjs --input /path/to/private-project/records.json
```

یا از ورودی استاندارد بخوانید:

```bash
node scripts/validation/validate-records.cjs --stdin < /path/to/private-project/records.json
```

ورودی یک شیء رکورد یا آرایهٔ غیرخالی رکوردهاست. CSV، JSONL، YAML و پوشش‌هایی مانند `{"records": [...]}` پذیرفته نیستند. چند فایل باید آگاهانه در یک آرایه جمع شوند؛ ابزار پوشه‌ها را جست‌وجو نمی‌کند. فرم‌های [templates](../../templates/README.md) تبدیل خودکار به JSON ندارند.

### ارجاع‌های بیرونی

پیش‌فرض سخت‌گیرانه است: شناسه و نسخهٔ هر مقصد باید در ورودی حاضر باشند. نسخهٔ دیگری از همان شناسه جای مقصد را نمی‌گیرد.

برای بررسی یک بخش ناتمام، فقط با انتخاب صریح:

```bash
node scripts/validation/validate-records.cjs --input /path/to/partial-records.json --allow-external-refs
```

این گزینه ارجاع گم‌شده را از خطا به هشدار تبدیل می‌کند؛ آن را پیدا یا تأیید نمی‌کند. نتیجه `relationships_complete: false` دارد. این گزینه خطاهای دیگر را نمی‌پوشاند و نباید برای پنهان‌کردن نقص پرونده به کار رود.

## معنی گزارش و کد خروج

- `0`: در کنترل‌های اجراشده خطا یافت نشد؛ ممکن است هشدار یا ارجاع حل‌نشده وجود داشته باشد.
- `1`: رکوردها در کنترل ساختار یا رابطه رد شدند.
- `2`: ورودی، خواندن فایل، JSON یا آماده‌سازی اعتبارسنج مشکل دارد.

گزارش JSON در خروجی استاندارد نوشته می‌شود. `--help` متن راهنما می‌دهد.

- `valid` و `status` فقط به دامنهٔ `structure_and_declared_relationships` مربوط‌اند.
- `records_received` تعداد ورودی‌ها و `records_checked` تعداد موارد واقعاً بررسی‌شده‌اند. عبور از حد تعداد، پیش از بررسی رکوردها متوقف می‌شود.
- `checks_run` کنترل‌های اجراشده را فهرست می‌کند. خطای schema مانع ورود به کنترل‌های رابطه‌ای می‌شود.
- `record_index` از صفر شروع می‌شود. مقدار `null` یعنی مشکل کل ورودی است.
- خطای `SCHEMA` نام قاعده و مسیر آن در schema را دارد، نه مقدار حساس، شناسه، نام فیلد دلخواه یا متن منبع.
- تنها نخستین خطای schema هر رکورد گزارش می‌شود؛ شمارنده‌ها تعداد همهٔ مشکلات ممکن نیستند. پس از اصلاح دوباره اجرا کنید.
- `relationships_complete` فقط می‌گوید ارجاع‌های بررسی‌شده مقصد یکتای حاضر دارند؛ درستی محتوا یا نبود چرخه را تضمین نمی‌کند.
- حداکثر ۱۰۰ مورد خطا و هشدار نمایش داده می‌شود؛ شمارنده‌ها حفظ می‌شوند و `issues_truncated` حذف جزئیات را نشان می‌دهد. نمایش خطا بر هشدار اولویت دارد.
- `not_verified` چیزهایی را می‌گوید که این ابزار تأیید نکرده است.

`valid: true` را به «آمادهٔ انتشار» تبدیل نکنید. حتی یک پروندهٔ ساختگی هم می‌تواند کاملاً معتبر باشد؛ نمونهٔ همراه عمداً همین را نشان می‌دهد.

## کنترل‌های پیاده‌شده

- نوع رکورد، نسخهٔ schema، فیلدهای ضروری، فیلد اضافی و قالب تاریخ، زمان و URI؛ بدون تغییر نوع، افزودن پیش‌فرض یا حذف خطا؛
- یکتایی شناسه و نسخه، حضور مقصد دقیق و نبود چرخه در منشأ منابع؛
- تقدم `created_at` بر `updated_at` و ترتیب بازه‌های میلادیِ نرمال‌شده؛ ثانیهٔ کبیسه‌ای که محیط نتواند مقایسه کند صریحاً رد می‌شود؛
- نام تکراری متغیر و وجود متغیر عددی برای وزن اعلام‌شده؛
- برای یافتهٔ checked با استنباط جمعیتی و نمونه‌گیری احتمالی، وجود وزن اعلام‌شده؛ برای پوشش اداری، غیراحتمالی و نامعلوم هشدار بازبینی؛
- شاهد مؤثر برای داوری تصمیم‌گرفته‌شده و سطح مطالعهٔ `full` یا `partial` برای منبع آن؛ ارجاع به یافتهٔ draft پذیرفته نمی‌شود؛
- رد یافتهٔ checked یا تحویل ready وقتی بررسی مرتبطِ ثبت‌شده failed یا blocked است؛
- هشدار دربارهٔ زنجیرهٔ شواهد مشترکِ اعلام‌شده، استقلال نامعلوم، واحد دادهٔ نامعلوم و تأیید انتشارِ صرفاً اعلام‌شده.

متغیر وزن فقط در فرهنگ داده بررسی می‌شود؛ خود داده، وزن‌ها و روش برآورد خوانده نمی‌شوند. `partial` بیان کاربر دربارهٔ مطالعه است، نه اثبات مرتبط‌بودن بخش خوانده‌شده. تشخیص استقلال بر شناسه و گروه ثبت‌شده تکیه دارد، نه تحلیل محتوای وب.

### چند کد قابل‌پیگیری

- ساختار: `SCHEMA`، `UNKNOWN_RECORD_TYPE`، `RECORD_OBJECT_REQUIRED`، `UNSAFE_RECORD_VERSION`.
- ارجاع: `MISSING_REFERENCE`، `DUPLICATE_RECORD_VERSION`، `SOURCE_LINEAGE_CYCLE`.
- رابطه و وضعیت: `UNINSPECTED_DECISIVE_SOURCE`، `NO_DECISIVE_EVIDENCE`، `UNCHECKED_FINDING_FOR_DECIDED_CLAIM`، `UNRESOLVED_HANDOFF_CHECK`.
- خواندن و قالب: `INPUT_READ`، `REGULAR_FILE_REQUIRED`، `INVALID_UTF8`، `JSON_PARSE`، `DUPLICATE_JSON_KEY`.
- حد و آماده‌سازی: `INPUT_SIZE_LIMIT`، `JSON_DEPTH_LIMIT`، `RECORD_COUNT_LIMIT`، `VALIDATOR_SETUP`.

سایر کدهای کنترل‌شده در `records.cjs` و آزمون‌های آن تعریف شده‌اند.

## حدهای اجرا و امنیت

خط فرمان: حداکثر ۲ MiB ورودی UTF-8، عمق JSON برابر ۶۴ و ۱۰۰۰ رکورد. کلید تکراری، حتی با نگارش escape معادل، رد می‌شود. فهرست فایل یا URL دریافت‌شده از داخل رکورد دنبال نمی‌شود؛ فیلد `$schema` در ورودی حق بارگذاری schema جدید نمی‌دهد.

ابزار URL باز نمی‌کند، دستور یا محاسبهٔ داخل رکورد را اجرا نمی‌کند و فایل ورودی را بازنویسی نمی‌کند. آدرس ورودی باید مسیر فایل عادی محلی باشد؛ `https:` و `file:` پذیرفته نیستند. مسیر انتخاب‌شده با دسترسی سیستم‌عامل جاری خوانده می‌شود؛ پیوند نمادین یا دیسک شبکه‌ای به‌وسیلهٔ سیستم‌عامل قابل‌دسترسی است. این ابزار sandbox یا مرز دسترسی نیست؛ فقط روی نسخهٔ مورداعتماد کد و schemaها اجرا شود.

گزارش تلاش می‌کند متن حساس را بازتاب ندهد، اما ابزار یافتن اسرار یا ناشناس‌سازی نیست. مسیرهای خط فرمان ممکن است در تاریخچهٔ پوسته ثبت شوند. گزارش و ورودی واقعی را بدون بررسی و اختیار منتشر نکنید.

تجزیهٔ JSON از `JSON.parse` و عددهای IEEE-754 استفاده می‌کند؛ حساب ده‌دهی دقیق، جلوگیری از همهٔ گردشدن‌های ورودی یا بررسی واحد مالی واقعی ارائه نمی‌شود. شمارهٔ نسخه باید عدد صحیحِ امن JavaScript باشد. عددهای بسیار بزرگ، اعشار دقیق و مقدار اصلی را آگاهانه مدل کنید و `original_value` را نگه دارید؛ این ابزار جای محاسبات دقیق یا مهاجرت قرارداد عددی نیست.

## استفاده از کتابخانه

```javascript
const {validateRecords} = require('./scripts/validation/records.cjs');
const report = validateRecords(parsedJson, {allowExternalRefs: false});
```

`parsedJson` باید دادهٔ سادهٔ حاصل از JSON باشد، نه شیء اجرایی، getter یا Proxy. تابع ورودی را تغییر نمی‌دهد. کنترل اندازه، UTF-8، کلید تکراری و عمق متن متعلق به خط فرمان است؛ فراخوان مستقیم باید ورودی را خودش محدود کند. خطای آماده‌سازی schema در API ممکن است استثنا ایجاد کند؛ خط فرمان آن را به `VALIDATOR_SETUP` تبدیل می‌کند.

## آزمون

از ریشهٔ مخزن:

```bash
node tests/schemas.test.cjs
node tests/validator.test.cjs
node tests/profiles.test.cjs
```

گزارش ثبت‌شده: ۱۷۸ آزمون موفق، صفر شکست با Node.js `v22.23.1`، Ajv `6.15.0` و js-yaml `4.3.2` در 2026-11-13. این نتیجه، ارزیابی مدل، آزمون همهٔ سیستم‌عامل‌ها، مجوز انتشار، نصب شبکه‌ای یا ممیزی امنیتی جامع نیست.
