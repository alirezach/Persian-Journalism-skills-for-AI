# قرارداد رکوردها

نسخهٔ schemaها: `0.1.0`؛ وضعیت: آزمایشی. گویش: JSON Schema Draft-07 برای سازگاری با اعتبارسنج موجود و امکان اجرای محلی. تغییر گویش در آینده نیازمند آزمون و مهاجرت است.

## فایل‌ها

| فایل | مسئولیت |
|---|---|
| `common.schema.json` | تعریف مشترک زمان، حریم خصوصی، واحد، مرجع نسخه‌دار و بررسی |
| `source-record.schema.json` | منبع، دسترسی واقعی، منشأ، استقلال و محدودیت استفاده |
| `claim-record.schema.json` | ادعا، شواهد، محل شاهد، داوری و موارد باز |
| `dataset-record.schema.json` | واحد مشاهده، جمعیت، دوره، جغرافیا، متغیر، وزن و کنترل کیفیت |
| `finding-record.schema.json` | روش، محاسبه، اندازه‌ها، عدم‌قطعیت و وضعیت بازتولید |
| `handoff.schema.json` | دامنهٔ تحویل، ورودی و خروجی، بررسی‌ها و موانع |

تعریف مشترک یک رکورد ششم نیست. پنج نوع رکورد داریم که از یک فایل تعاریف مشترک استفاده می‌کنند.

## قواعد استفاده

- نام فیلد و شناسه ماشینی است؛ متن انسانی می‌تواند فارسی باشد. ارقام نمایشی با مقدار ماشینی مخلوط نشوند.
- `schema_version` نسخهٔ قرارداد و `record_version` نسخهٔ محتوای یک شناسه است. هر ارجاع، هر دو جزء شناسه و نسخهٔ رکورد مقصد را نگه می‌دارد.
- فیلد ناشناخته رد می‌شود. مقدار نامعلومِ مجاز با `null` یا enum مربوط ثبت می‌شود، نه رشتهٔ خالی، عدد صفر یا مقدار ساختگی.
- `created_at` و `updated_at` زمان میلادی ISO با منطقهٔ زمانی‌اند. تاریخ و تقویم اصلی منبع در فیلد جدا حفظ می‌شوند. تبدیل شمسی در این نسخه پیاده‌سازی نشده است.
- `scale` ضریب مقیاس است، نه نرخ ارز. تبدیل واحد و نرخ باید در روش ثبت شوند. `IRT` در این پروژه کد محلی تومان است، نه کد ISO.
- نتیجهٔ checked با واحد نامعلوم، پول بدون مشخصات ارز، یا نرخ و نسبت بدون مخرج پذیرفته نمی‌شود. معنای واقعی واحد و مخرج همچنان بازبینی می‌خواهد.
- `original_value` برای حفظ بیان اصلی مقدار است. برای محاسبات مالی دقیق و اعداد بزرگ، مصرف‌کننده باید دقت عددی مناسب داشته باشد؛ آزمون JavaScript مجوز استفادهٔ بی‌احتیاط از عدد ممیز شناور نیست.
- وضعیت approved در حریم خصوصی به ارجاع بازبینی واقعی نیاز دارد و به‌تنهایی اختیار ارسال یا انتشار نمی‌دهد.
- ready در تحویل یعنی آمادهٔ مرحلهٔ بعد در دامنهٔ ثبت‌شده، نه تأیید انتشار.

## بارگذاری محلی

همهٔ شش فایل را در یک اعتبارسنج Draft-07 ثبت کنید؛ سپس رکورد را با شناسهٔ schema متناظر بسنجید. شناسه‌ها URN هستند؛ نباید به وب فرستاده شوند. `common.schema.json` باید هنگام نصب همراه رکوردها باشد. فعال‌کردن بررسی `format` برای تاریخ، زمان و URI لازم است؛ تغییر نوع، افزودن پیش‌فرض و حذف فیلد اضافی نباید خطا را پنهان کند.

نسخه‌های `schema_version` متفاوت به‌صورت خودکار ادغام نمی‌شوند. مهاجرت باید اصل رکورد و سابقهٔ تغییر را حفظ کند.

## اجرای آزمون

در محیطی با Node.js و وابستگی مجازِ نصب‌شده:

```bash
node tests/schemas.test.cjs
```

در صورت نیاز به نصب، ابتدا `tests/package.json` و وابستگی را بررسی کنید؛ این دستور به دسترسی شبکه و سیاست نصب محیط وابسته است:

```bash
npm --prefix tests install --ignore-scripts --no-audit --no-fund
npm --prefix tests test
```

در بررسی محلی 2026-11-13، با Node.js `v22.23.1` و Ajv `6.15.0`، تعداد ۶۷ آزمون گذشت و هیچ‌کدام شکست نخورد. از وابستگی ازپیش‌نصب‌شده استفاده شد؛ فرمان نصب شبکه‌ای اجرا نشد. فایل قفل کامل وابستگی‌های فرعی و خط CI هنوز ارائه نشده‌اند. محیط دیگر و نسخهٔ دیگر باید دوباره آزموده شوند.

## پوشش واقعی

آزمون‌ها شامل اعتبار خود schema، پنج رکورد مصنوعی، رد فیلد و نسخهٔ نامعتبر، تمایز صفر و گمشده، واحد و ارز، مخرج، سابقهٔ بررسی، مرجع و نسخهٔ گم‌شده، شناسهٔ تکراری، وزن، دورهٔ معکوس و چرخهٔ منشأ هستند. آزمون‌های ارتباطی در فایل آزمون نمونه‌اند؛ هنوز اعتبارسنج عمومیِ ورودی کاربر ارائه نشده است.

مجموعهٔ رکوردها برای آزمون ارتباطی باید تمام مقصدهای ارجاع‌شده را داشته باشد. در کاربرد واقعی، ارجاع بیرونی حل‌نشده باید اعلام شود، نه اینکه شاهد موجود فرض شود.

## چه چیزی تأیید نمی‌شود؟

این مرحله حقیقت ادعا، درستی روش آماری، اعتبار مجوز، کفایت ناشناس‌سازی، صحت تبدیل تقویم، عضویت تمام کدهای ارز در ISO یا اختیار واقعی یک فرد را اثبات نمی‌کند. آزمون رفتاری مدل، بررسی امنیتی جامع، سازگاری اسکیل با محصولات و قابلیت انتشار هم اجرا نشده‌اند.

نمونه‌ها همگی مصنوعی‌اند؛ آدرس example.org و نقش‌های fixture شاهد یا تأیید واقعی نیستند. بررسی پوشش و کیفیت شواهد همچنان طبق استانداردهای مشترک انجام می‌شود.
