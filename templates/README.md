# الگوهای کاری

این الگوها فرم‌های انسانی‌اند؛ نه مدرک انجام بررسی، نه رکورد JSON آماده و نه مجوز انتشار. جای‌خالی‌ها را با اطلاعات واقعی پر کنید یا صریحاً «نامعلوم / بررسی‌نشده» بنویسید.

اکنون ۱۱ الگوی کاری وجود دارد؛ این README در شمار الگوها نیست. دو فرم تازهٔ نامزدهای ۰.۱.۱، ماتریس شواهد و بازبینی نمایش‌اند.

| فایل | کاربرد |
|---|---|
| `project-brief.md` | سؤال، دامنه، نوع مداخله، پروفایل، منابع و اختیار |
| `translation-decisions.csv` | اصطلاح، معنای بافتی، معادل و دلیل انتخاب |
| `claim-ledger.csv` | ثبت ادعا، شاهد، نتیجه و بررسی باز |
| `data-dictionary.csv` | یک ردیف برای هر متغیر و تعریف واحد و مقادیر گمشده |
| `methodology.md` | توضیح عمومی داده، روش، محدودیت و کنترل واقعی |
| `publication-checklist.md` | ثبت بازبینی و موانع انتشار، بدون تأیید خودکار |
| [source-claim-human-review.md](source-claim-human-review.md) | بازبینی انسانیِ مرز منبع و ادعا، کفایت شواهد و آمادگی تحویل در دامنهٔ مشخص |
| `correction-log.csv` | خطا یا به‌روزرسانی، نسخه‌های متأثر و وضعیت اصلاح |
| `handoff.md` | تحویل دامنه‌دار به مرحلهٔ بعد |
| [evidence-matrix.csv](evidence-matrix.csv) | هر ردیف یک یافتهٔ منبع؛ با تفکیک استنباط تحلیلگر، دامنه، استقلال و بررسی باز |
| [visualization-review.md](visualization-review.md) | ثبت تطبیق عدد، صداقت بصری، فارسی، دسترس‌پذیری و خطر افشا در خروجی مشخص |

در ماتریس شواهد، `source_ref` و `source_version` به مرجع واقعی اشاره کنند؛ متن ارجاع لزوماً رکورد JSON نیست. `source_finding` را با `analyst_inference` جابه‌جا نکنید. چند ردیف از یک پژوهش، چند شاهد مستقل محسوب نمی‌شوند. فرم نمایش نیز بدون مشاهده و بررسی واقعی خروجی، قبولی ایجاد نمی‌کند.

## بازبینی قرارداد منبع و ادعا

چک‌لیست `source-claim-human-review.md` بر پایهٔ [مرز عملیاتی اسکیل‌ها](../docs/skill-boundaries.md) و [نگاشت قرارداد به schemaها](../schemas/README.md) است. برای هر بند، وضعیت و شاهد یا دلیل ثبت می‌شود؛ فرم خالی، تیک‌ها یا شمار تأییدها نشانهٔ قبولی نیستند. وضعیت بندهای فرم با نتیجهٔ ادعا یا وضعیت بررسی در JSON یکی نیست و تبدیل خودکار ندارد. تکمیل بازبینی می‌تواند به تشخیص نقص و مسدودشدن تحویل منتهی شود. این فرم جای چک‌لیست انتشار یا مجوز انتشار را نمی‌گیرد.

## CSV و JSON

CSVها فقط سرستون دارند؛ هیچ مثال ساختگیِ قابل‌اشتباه با دادهٔ واقعی در آن‌ها نیست. این فرم‌ها تبدیل بدون‌اتلاف schemaها نیستند. فیلدهای تو‌در‌تو مثل شواهد، در صورت استفاده، به‌صورت JSON معتبر در سلول `evidence_json` نوشته می‌شوند. تبدیل خودکار CSV به رکورد در این نسخه وجود ندارد.

[اعتبارسنج عمومی](../scripts/validation/README.md) فقط رکورد JSON یا آرایهٔ رکوردها را می‌پذیرد. رشتهٔ خالی CSV، در هنگام ساخت رکورد، نباید بی‌دلیل صفر یا تأیید تلقی شود. `null` و وضعیت نامعلوم مطابق [schemaها](../schemas/README.md) ثبت شوند.

- `evidence_json` شواهد موافق، مخالف و زمینه‌ای و محل دقیق شاهد را نگه می‌دارد؛ `finding_refs_json` و `source_refs_json` ارجاع با شناسه و نسخه‌اند، نه صرفاً نام فایل.
- `as_of_original` و `as_of_calendar` دوره و تقویم منبع را حفظ می‌کنند؛ `as_of_start` و `as_of_end` فقط کران میلادیِ واقعاً تبدیل و کنترل‌شده‌اند. نامعلوم را حدس نزنید.
- `currency_namespace` کد ISO را از کد محلی پروژه جدا می‌کند؛ `IRT` برای تومان در این پروژه محلی است. `scale` ضریب مقیاس است، نه نرخ تبدیل ارز.
- ستون status در هر فرم معنای همان کار را دارد. هنگام ساخت رکورد، enum مربوط را از schema انتخاب کنید؛ «بررسی‌نشده» را به verified یا approved تبدیل نکنید.

هنگام بازکردن CSV دریافت‌شده از منابع بیرونی در Excel یا نرم‌افزار مشابه، خطر تفسیر سلول به‌صورت فرمول را بررسی کنید. این فرم‌های خالی ابزار پاک‌سازی فرمول یا دادهٔ نامطمئن نیستند.

نسخهٔ پرشده ممکن است حساس باشد و باید در پروندهٔ خصوصی پروژه نگهداری شود، نه در پوشهٔ عمومی الگوها. نمونه‌های حساس یا کلیدها را در جای‌خالی‌های این مخزن وارد نکنید.
