# سازگاری و حدود اجرا

## وضعیت واقعی

هیچ محیط میزبان اسکیل آزموده نشده است. ۱۷۸ آزمون محلی قرارداد، اعتبارسنج، خط فرمان، پروفایل و الگو با Node.js v22.23.1، Ajv 6.15.0 و js-yaml 4.3.2 گذشت. این نتیجه به سازگاری مدل، محصول، همهٔ سیستم‌عامل‌ها یا نمایش RTL تعمیم داده نمی‌شود. نصب شبکه‌ای و فرمان‌های npm اجرا نشدند. هنوز بستهٔ نصب اسکیل یا سازگارساز ارائه نشده؛ جدول زیر برنامهٔ پشتیبانی است، نه گواهی عملکرد.

[اعتبارسنج محلی](../scripts/validation/README.md) مستقل از میزبان اسکیل اجرا می‌شود. پروفایل‌ها راهنمای اعلامی‌اند؛ بارگذاری YAML به معنی اجرای سبک، ادغام تنظیمات یا اصلاح خودکار متن نیست.

| محیط هدف | مسیر پیشنهادی | وضعیت |
|---|---|---|
| Claude و Claude Code | بستهٔ استاندارد و تنظیمات متناسب با محصول | برنامه‌ریزی‌شده؛ آزمون‌نشده |
| Codex | بستهٔ استاندارد و فرادادهٔ محیط | برنامه‌ریزی‌شده؛ آزمون‌نشده |
| Gemini و Gemini CLI | بسته یا راهنمای متناسب با محصول | برنامه‌ریزی‌شده؛ آزمون‌نشده |
| ClickUp | تبدیل به اسکیل و منابع قابل‌بارگذاری | برنامه‌ریزی‌شده؛ آزمون‌نشده |
| محیط چت متنی | فایل مستقل برای هر اسکیل و دستور فعال‌سازی کوتاه | برنامه‌ریزی‌شده؛ آزمون‌نشده |

محصولات چت، CLI و API یک سازنده می‌توانند قابلیت متفاوت داشته باشند. پشتیبانی یکی به دیگری تعمیم داده نمی‌شود. مسیر نصب باید هنگام پیاده‌سازی با مستندات جاری همان محصول تأیید شود.

## سه سطح قابلیت

### راهنمای متنی

ویرایش، ترجمه، طرح بررسی و تحلیل شواهد ارائه‌شده ممکن است. اجرای اسکریپت، دریافت اینترنتی یا اعتبارسنجی فایل بدون ابزار قابل‌ادعا نیست. راهنمای دستی نباید «آزمون خودکار گذشت» گزارش شود.

### فایل و کد

اجرای کد و خواندن فایل در محدودهٔ محیط ممکن است. بسته باید وابستگی‌ها، نسخه‌ها، ورودی و خروجی را مشخص کند. وجود ابزار به معنی اجرای موفق یا تأیید روش نیست؛ نتیجه باید بررسی شود.

### اتصال به سرویس‌ها

بازیابی منبع یا انتقال مجاز امکان‌پذیر می‌شود. دسترسی، محرمانگی و اختیار هر عمل جدا بررسی می‌شوند. اتصال فنی مجوز تماس، انتشار یا انتقال دادهٔ محدود نیست.

## قرارداد ساخت بسته

- منبع اصلی در مخزن نگهداری شود؛ خروجی‌های محیطی دستی واگرا نشوند.
- هر اسکیل نصب‌شده منابع لازم را همراه داشته باشد.
- وابستگی اجباری، همکاری اختیاری و محدودیت جایگزین روشن باشند.
- نسخهٔ متنی، ادعاهای وابسته به ابزار را به محدودیت صریح تبدیل کند.
- فایل عمومی یک اسکیل نباید کل دانش نامرتبط ریپو را بارگذاری کند.
- نام و شرح اسکیل زمان فعال‌شدن را مشخص کنند؛ بارگذاری فایل دانش به‌تنهایی اجرای آن را تضمین نمی‌کند.
- انتشار شامل نسخه، فهرست فایل و مجوزهای لازم باشد.

## شواهد لازم برای ادعای سازگاری

نام محصول، نسخه یا تاریخ سرویس، مدل در صورت دسترس، سطح قابلیت، روش نصب، شناسهٔ بسته، نمونهٔ آزمون، نتیجه و محدودیت ثبت شوند. اطلاعات دسترس‌ناپذیر حدس زده نشوند.

آزمون لازم: کشف اسکیل، فعال‌سازی درست، دسترسی به منابع، عدم شکست مسیرها، رفتار در نبود ابزار و حفظ دامنهٔ اختیار. سازگاری باید با نمونهٔ واقعی سنجیده شود، نه صرفاً معتبر بودن YAML.
