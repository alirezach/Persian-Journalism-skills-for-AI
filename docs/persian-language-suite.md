# مجموعهٔ ویرایش و دیتاکس فارسی

نسخهٔ مجموعه: 0.1.0، تاریخ نسخه: 2026-11-17؛ به‌روزرسانی مستندات: 2026-11-18. این بازطراحی با [PR شمارهٔ ۱](https://github.com/alirezach/Persian-Journalism-skills-for-AI/pull/1) در ۱۷ نوامبر در main ادغام شد. شناسهٔ پروژه 0.4.3-editing تغییر نکرده است؛ این ثبت به معنی Release/tag، نصب یا پذیرش رفتاری نیست.

## سه مسئولیت، نه سه اجرای تکراری

| مهارت | نسخه | کاربرد |
|---|---|---|
| [persian-editing](../skills/persian-editing/README.md) | 0.2.0 | ویراستاری فنی و زبانی؛ نه بازنویسی آزاد، تغییر مخاطب، تلخیص یا مأموریت دیتاکس |
| [persian-ai-detox](../skills/persian-ai-detox/README.md) | 0.1.0 | اصلاح الگوهای قالبی نثر با حفظ صدا، معنا و شواهد؛ نه تشخیص نویسنده یا دورزدن آشکارساز |
| [persian-editing-and-ai-detox](../skills/persian-editing-and-ai-detox/README.md) | 0.2.0 | هر دو جزء کامل، با انتخاب فقط ویرایش، فقط دیتاکس یا اجرای ترکیبی |

هر سه experimental هستند. «ویرایش کن» به‌تنهایی یعنی ویرایش زبانی محافظه‌کارانه، نه دیتاکس خودکار. ویرایش سنگین‌تر می‌تواند جمله را موضعی اصلاح کند؛ مجوز افزودن مثال، حذف ادعا، بازچینی استدلال یا اصلاح واقعیت نیست.

## منابع و میزان پوشش

ویرایش از گردآوری ارسالی Persian_Editing_Principles_Zolfaghari.md اقتباس شده است. اصل کتاب بررسی نشده و گردآوری از بازسازی برخی مثال‌ها و نبود بعضی جدول‌ها خبر می‌دهد. [ماتریس پوشش](../skills/persian-editing/references/source-coverage.md) همهٔ سرفصل‌های گردآوری را به راهنماها نگاشت می‌کند؛ ادعای بازتولید تمام مثال‌ها یا اصل کتاب ندارد. چهارده راهنمای تخصصی، نقش ۱۸ نشانه، رسم‌الخط، املا، نام‌ها، آوانگاری، اعداد، تاریخ، فرمول، ارجاع، آماده‌سازی اثر، واژگان و دستور را پوشش می‌دهند.

دیتاکس از [persian-writing](https://github.com/ali2000hos/persian-writing) در commit مشخص 75fcdf313fab65d6d205500ca50f9cb52db25783 اقتباس شده است. کاتالوگ T1 تا T18 و راهنماهای گونه، نثر علمی، ساختار، ریتم و کنترل کیفیت کامل‌اند. مجوز MIT و منشأ فایل‌های استفاده‌شده همراه بسته‌اند. واژهٔ رایج، مجهول یا فهرست سه‌تایی به‌تنهایی عیب یا شاهد تولید ماشینی نیست. برای طبیعی‌کردن متن، داده، تجربه، شاهد یا عامل ناشناخته ساخته نمی‌شود.

## ساخت مستقل و مجموعه

از ریشهٔ مخزن با Python 3.10+ و کتابخانهٔ استاندارد:

```bash
python3 scripts/packaging/build-persian-language-suite.py --skill persian-editing --format standalone --output dist/persian-editing-0.2.0.zip
python3 scripts/packaging/build-persian-language-suite.py --skill persian-ai-detox --format standalone --output dist/persian-ai-detox-0.1.0.zip
python3 scripts/packaging/build-persian-language-suite.py --skill persian-editing-and-ai-detox --format standalone --output dist/persian-editing-and-ai-detox-0.2.0.zip
python3 scripts/packaging/build-persian-language-suite.py --output dist/pjai-persian-language-suite-0.1.0-opencode.zip
python3 scripts/packaging/build-opencode.py --output dist/pjai-opencode-0.2.0.zip
```

خروجی باید ناموجود باشد. فرمان آخر همان هشت مهارت اصلی را می‌سازد و فقط ویرایش را به ۰.۲.۰ می‌رساند؛ دیتاکس مستقل و ترکیبی در بستهٔ سه‌مهارتی‌اند. وجود ده مدخل کاتالوگ به معنی ده مهارت در بستهٔ هشت‌مهارتی نیست.

`build-editing-detox.py` برای سازگاری فرمان قبلی حفظ شده، ولی فقط شناسهٔ جدید ترکیبی را تولید می‌کند. بازسازی نسخهٔ تاریخی از شاخهٔ جاری ممکن نیست؛ برای آن باید commit تاریخی دقیق استفاده شود.

## کامل‌بودن بستهٔ ترکیبی

سازنده از خروجی مستقل ویرایش و دیتاکس استفاده می‌کند، نه از خلاصه‌سازی منابع. تمام ۲۶ فایل بستهٔ ویرایش و ۱۳ فایل دیتاکس با همان بایت‌ها در components قرار می‌گیرند. فقط نام ورودی داخلی SKILL.md به INSTRUCTIONS.md تبدیل می‌شود. مسیرهای مرجع هر جزء نسبت به ریشهٔ همان جزء هستند.

manifest بیرونی نگاشت مسیر اصلی، مسیر داخلی و SHA-256 هر فایل را ثبت می‌کند. manifestهای اصلی داخل اجزا برای منشأ حفظ می‌شوند؛ برای اعتبارسنجی مسیر تغییرنام‌یافته باید نگاشت بیرونی را اعمال کرد. منابع مستقل دوباره تألیف یا کوتاه نمی‌شوند و نصب مهارت‌های همسایه لازم نیست.

## مهاجرت

۱. نسخهٔ نصب‌شده و تغییرات محلی را ثبت و پشتیبان بگیرید.
۲. ZIP جدید را در پوشهٔ موقت باز و نسخه‌ها و manifest را بررسی کنید.
۳. برای استفادهٔ ترکیبی، شناسهٔ جدید را انتخاب کنید. مسیر قدیمی persian-editing-detox را هم‌زمان برای همان درخواست فعال نکنید.
۴. حذف یا جایگزینی نصب محلی به تصمیم خود کاربر است؛ هیچ سازنده‌ای آن را انجام نمی‌دهد. ده فایل منبع قدیمی در شاخهٔ کاری پس از تأیید جایگزین حذف شدند و نتیجه با PR شمارهٔ ۱ به main رسید؛ این کار نصب محلی کاربران را تغییر نداده است.
۵. پس از نصب اختیاری، کشف نام، خواندن یک مرجع داخلی هر جزء و رفتار مجوزها را در میزبان واقعی بررسی کنید. این بررسی در ساخت فنی انجام نشده است.

## آزمون و محدودیت

[گزارش اجرای کامل ۱۷ نوامبر](evaluations/main-full-tests-2026-11-17.md) برای کامیت ادغام، ۴۵۵ کنترل فنی مستقل موفق و صفر شکست ثبت می‌کند. فرمان‌های زیر زیرمجموعهٔ مرتبط با این راهنما هستند، نه کل مجموعه‌آزمون مخزن؛ برای اجرای کامل و پرهیز از دوباره‌شماری، [راهبرد آزمون جاری](testing-strategy.md) را ببینید. این گزارش پذیرش رفتار مدل یا میزبان نیست.

```bash
python3 -m unittest discover -s tests -p 'test_persian_language_suite.py' -v
python3 -m unittest discover -s tests -p 'test_editing_detox_build.py' -v
python3 -m unittest discover -s tests -p 'test_editing_build.py' -v
python3 -m unittest discover -s tests -p 'test_opencode_build.py' -v
node tests/editing-package.test.cjs
node tests/editorial-sources.test.cjs
node tests/profiles.test.cjs
```

آزمون‌ها قرارداد فایل، نسخه، مسیر، هش، یکسانی اجزا، ساخت تکرارپذیر و جلوگیری از بازنویسی خروجی را بررسی می‌کنند. این‌ها پذیرش رفتاری، ارزیابی انسانی، گواهی امنیت جامع یا اجرای OpenCode نیستند. سناریوهای تازه در مثال‌های ویرایش و acceptance-cases دیتاکس آماده‌اند اما اجرا نشده‌اند. منابع و خروجی‌های تاریخی دست‌نخورده‌اند؛ هیچ نتیجهٔ قدیمی به نسخه‌های جدید منتقل نمی‌شود.
